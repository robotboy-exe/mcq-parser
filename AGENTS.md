## Editing rules

- `src/bookmarklet.js` and `src/bookmarklets/key/bookmarklet.js` are generated; never edit them by hand. Edit `src/parser/core.js` + `src/bookmarklets/stimulus/autosave.js` + `src/ui/ui.js` or `src/bookmarklets/key/boot.js` + `entry.js`, then rebuild. `src/parser/parser.js` is only a Node facade and is never inlined. `src/bookmarklet.min.js` is an untracked local artifact; do not edit, rely on, or rebuild it.
- Full-line `//` comments are stripped by the build; never add inline `//` comments, because the build flattens everything onto one `javascript:` line and an inline `//` truncates the rest. Do not rely on indentation in multiline template literals; the build trims every line.
- The production OCR helper is root `ocr_helper.js`, loaded directly by `admin_questions.php` after `src/parser/core.js`; the helper is a thin adapter and owns no parsing implementation of its own. It is the deployed manual product only: it must never regain answer-key load, dry run, autosave, in-place save, image plan, batch history, or a bookmarklet title. That behavior lives in `src/bookmarklets/key/entry.js` and reaches users only through the generated key bookmarklet. Do not modify the PHP server contract: CSRF, PRG flow, field names, four-option rule, and success flash text are fixed.
- Field contract (`docs/SPEC.md` §3.5, D-109, INV-154/155): `question_text` and options A–D never receive section headings, instruction lines, dividers, shared stimulus/table text, E/F options, the answer key, or question numbers. Drop out-of-scope lines; never reassign them to the nearest field. `sectionInstruction`/`regions` are internal metadata the root helper never surfaces.
- Do not change `localStorage` key names/shapes: `ocrQueue`, `ocrMeta`, `ansKey`. Root `ocr_helper.js` keeps the legacy `ocrSubmitted` marker (written on submit, deleted on the next load); do not add that key to new modules, and the archived bookmarklet must not touch it.
- Preserve deliberate quirks: E/F→D collapse, `splitQuestions` numbering guard, advisory-only flags, blank options, `FIXES` order. Do not refactor for style.
- Preserve multiline rendering: root helper folds single wraps but keeps blank-line paragraphs (`\n\n`), options stay single-line, and Constant Text/question stems use `white-space: pre-wrap` in the CBT pages.
- `src/question-preview.js` is read-only: it renders Constant Text and Question through `window.CBTText`, writes no form values, and has no storage/network behavior. The Constant Text preview is a fixed 150px border-box with vertical scrolling; the Question preview remains content-sized. Root `ocr_helper.js` must not reference or fill `constant_text`.
- `src/math-tool.js` is the admin operator row, five freeform shape editors (fraction, exponent, subscript, root, 2×2 matrix), and advisory byte counter for `#question_text`. The basic operator row excludes `√`, so the visual Root editor is the only square-root control. A `More symbols` drawer restores only the Greek, set theory and logic, and geometry and vectors grids; the exponent, subscript, fraction, and square-root characters stay out of the palette because the visual editors cover them. It emits only the exact shape markers, refuses `<`, `>`, and the separator that would split the active shape, and writes no storage, network, form submit, underline marker, or `constant_text` behavior; the server's 60,000-byte check and the native `maxlength` stay authoritative.
- Only the six exact marker pairs are formatting: `<u>`, `<frac>`, `<sup>`, `<sub>`, `<sqrt>`, and `<matrix>`. `src/owner-tool/render.js` and `deployed/render.php` must stay paired on the shared vectors in `tests/fixtures/render-markup.json`; keep fraction bars horizontal and keep the radical vinculum visibly joined to the glyph on every rendering surface (D-97, D-98, D-103).
- `deployed/cbt_question_order.php` reorders only the already-selected rows for the trusted exact subject name `English (Lexis & Structure)`. Keep the SQL filters, `ORDER BY RAND()`, limit, ID multiset, original-order members (ascending `id` inside each group), blank singleton behavior, and per-row Constant Text rendering unchanged.
- `deployed/subject_display.php` maps only that exact stored name to `English (Comprehension Pages / Lexis & Structure)` on `admin_questions.php` and `cbt.php`. Keep form values as IDs, pass the raw database name to ordering, and require no SQL rename. In `cbt.php`, Constant Text stays weight 800 and the still-bold question stem stays weight 700.
- D-91 is the root-helper option-label contract: A-D is case-insensitive; whitespace is optional after `(`, before `)`, and before `.`, while unspaced forms remain valid. A later label-like repeat of an already selected letter stays in that option's text. The review-settled phase-1 implementation includes the exact `A) ... A ) ... B)` regression.
- Treat divider-only runs of three or more equals signs (`========`) as section separators (D-46). A partial section, even one question, is its own paste; do not attach an unheaded section to the previous or next year.
- Highest-risk code: `OPTION`, the blank-option whitespace class, `LOOSE` E/F, `splitSections`, `splitQuestions`, and the paired `fillForm`/`tick` logic. See `docs/AGENTS.md` before changing these.
